# SumOffice

Status: draft, not yet submitted; needs republished multi-arch images (amd64+arm64) with the WOPI proof-key fix before submission.

[SumOffice](https://github.com/SumOfficeApp/sumoffice-docker) adds Excel- and Word-compatible browser editors to
Nextcloud Office and other WOPI hosts: SumSheet for workbooks (`.xlsx`, `.xlsm`, `.xlsb`) at `/f1` and SumDoc for
documents (`.docx`) at `/a4`, with a joint WOPI discovery at `/hosting/discovery`, all on one port.

After install, point Nextcloud Office at the app: Administration settings → Office → "Use your own server" →
the **Public URL** you entered. Nextcloud and the editor should use the same scheme (both http or both https).

## Packaging notes (for catalog reviewers and the owner)

This folder follows the `ix-dev/community/<app>` layout of https://github.com/truenas/apps
(`app.yaml`, `ix_values.yaml`, `item.yaml`, `questions.yaml`, `templates/docker-compose.yaml`,
`templates/test_values/`, `README.md`), modelled on `ix-dev/community/actual-budget` as of 2026-09.

- Image: the single image `hissih/sumoffice-aio` (SumSheet + SumDoc + joint discovery + front, see `aio/` on the
  `aio-single-image` branch). The catalog renders compose from templates and cannot ship the `nginx.conf` and
  `discovery.py` side files of the four-service stack, so the one-image build is used.
- `FRONT_PORT` makes the front listen on the chosen WebUI port inside the container (host port = container port,
  the catalog convention). Default port `30093` must still be checked against `.github/scripts/port_validation.py`.
- The WOPI proof key is generated on first start into `/data/proof` of the data storage and used by both editors.
- Health check runs `node` inside the image against `/health` of the front (no `curl` assumed in the image).
- `templates/library/` is not included and `lib_version_hash` is empty on purpose: both are generated by
  `devbox run copy-lib` in the truenas/apps checkout (library `2.3.14`, the newest at the time of writing).
- The template was rendered with library 2.3.14 against `basic-values.yaml` outside the official CI container;
  the official `./.github/scripts/ci.py --app sumoffice --train community --test-file basic-values.yaml` has not
  been run.

Assumptions to confirm before the PR:

1. The image runs as an arbitrary non-root user (568:568) with only `/data` writable (`HOME=/data/home` is set).
   If it needs root, change `run_as_context` and remove `set_user`.
2. `FRONT_PORT` is honoured by the published image (it is read by `aio/front.mjs`).
3. Category `productivity` is accepted by the catalog.
