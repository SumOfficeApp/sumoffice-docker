# K4 protocol — Box, Egnyte and kintone bridges

Date: 2026-10-05. No external account was created and nothing was deployed or
published. Each bridge is installable with one command after its uncommitted env
file has been filled. The API journeys below run against local protocol stubs.

## One-command installation

| Bridge | Command | Container | Port |
|---|---|---|---|
| Box | `./integrations/box/install.sh /secure/path/box-bridge.env` | `sumoffice-box-bridge` | 8796 |
| Egnyte | `./integrations/egnyte/install.sh /secure/path/egnyte-bridge.env` | `sumoffice-egnyte-bridge` | 8790 |
| kintone | `./integrations/kintone/install.sh /secure/path/kintone-bridge.env` | `sumoffice-kintone-bridge` | 8787 |

The scripts build from the checked-out source, replace only their exact named
container, set `--restart unless-stopped`, and never print the env file. Their
command wiring is tested with a fake Docker executable; that test does not start
a heavy image build.

## API-stub acceptance

| Bridge | Stub journey | Refusals covered | Result |
|---|---|---|---|
| Box | OAuth code → one-time editor link → CheckFileInfo → LOCK → GetFile redirect → PutFile new version | bad/reused code, expired link, forged proof, wrong session, missing lock, stale etag, read-only rights; no credentials in page or redirected download | green |
| Egnyte | invocation → one-time link → CheckFileInfo → LOCK → GetFile → versioned upload by path | wrong domain/folder, reused link, forged proof, wrong session, missing lock, read-only token; token absent from page | green |
| kintone | proxy ticket → CheckFileInfo → LOCK → GetFile → PutFile → UNLOCK | wrong secret/name/type/proof/session, missing lock, stale record revision; other attachment retained | green |

Commands:

```sh
node --test integrations/k4-one-command-install.test.mjs
node --test integrations/k4-format-matrix.test.mjs \
  integrations/box/bridge/test/bridge.test.mjs \
  integrations/egnyte/bridge/test/bridge.test.mjs \
  integrations/kintone/bridge/test/bridge.test.mjs
```

## Remaining live acceptance

- **Box:** the owner creates an OAuth 2.0 Custom App plus Web App Integration in
  a Box developer account and exposes the bridge through HTTPS.
- **Egnyte:** the owner requests a developer sandbox and Public API key through
  the Egnyte developer programme.
- **kintone:** the owner creates a developer domain, app and API token with View
  records and Edit records, then installs the signed plugin.

Only those accounts can prove the real SaaS callback shapes and permissions.
Until then this protocol claims the adapter contracts and rejection paths, not
a live Box/Egnyte/kintone round.
